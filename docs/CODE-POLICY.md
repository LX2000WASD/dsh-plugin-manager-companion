# 参考不复制：新仓库的代码引入规范

> 用户明确要求："对于旧有的可复用代码我们的态度是参考但不直接复制粘贴使用。
> 一方面是因为我们的代码有之前的包袱与依赖，一方面是我们的代码实际上可能有许多 BUG 和漏洞。"
> 本文把这条原则变成**可执行的准入规则**，避免执行时走样。

## 1. 三分类准入

每个要从旧仓库搬的能力，必须先归入以下三类之一，并在实现前写下归类理由。

### A 类：重写（默认）
**适用范围**：任何触碰官方契约、写文件、调子进程、管生命周期的代码。

判定：如果它 **import 官方包** / **写 profile 文件** / **起子进程** / **有状态**，一律重写。

理由：旧代码的这些部分是为"官方没有管理页"的世界写的，前提已经消失；
且调研已实证其中有真实缺陷（见 §3）。

### B 类：参考算法后重写（纯函数）
**适用范围**：无副作用的纯计算——打分、排序、标签、分类计数、模糊匹配。

判定：函数签名不含 `Context`/`fs`/`child_process`，输入输出都是 JSON-safe 数据。

做法：**读旧实现理解意图 → 写新实现 → 用旧实现的历史测试当对照**（不复制测试代码，复制用例语义）。

### C 类：仅作需求参考（不写代码）
**适用范围**：UI 交互、页面布局、文案组织。

做法：只看它解决了什么问题，用官方 primitives 重新设计。

## 2. 强制检查项（每个模块开工前）

写任何模块前，先回答：

1. **官方有没有现成的？** 有 → 直接用，不许重写（查 `./operations`、`./types`、`ctx.remote.*`、`ctx.settingsScope`）
2. **旧代码里对应的是什么？** 读它，理解它解决的问题
3. **它属于 A/B/C 哪类？** 写进模块头注释
4. **它的前提还成立吗？** 若前提消失（如"官方没有管理页"），结论必须重推

## 3. 已实证的旧代码缺陷（重写时必须避开）

| # | 缺陷 | 证据 | 新仓库如何避免 |
|---|---|---|---|
| 1 | bundle patch 行 id 与官方撞车 | `cordis.patch.yml` 的 `id: plugin-manager`；实测 `duplicate loader entry id`，profile 崩 | 行 id 用 `dsh-plugin-manager-companion`；**加启动自检** |

| 3 | fiber 相位映射错 | 旧 `phaseOf`：`4→null`、`5→unloading`；官方 `FiberState`：`4=DISPOSED, 5=UNLOADING` | 用官方 `PluginFiberPhase` 类型；**不自己定义数值映射** |
| 4 | tsconfig include 缺口 | `marketplaceMerge.ts` 不在 `tsconfig.host.json`，靠传递依赖编译 | 加**构建后产物清单断言**测试 |
| 5 | 自建 REST 与官方 Remote 并存 | 27 个 op + job 系统 | 全删，用官方 Remote |

## 5. 每个模块的交付模板

```ts
/**
 * <模块名> — <一句话职责>
 *
 * 归属：<A 重写 | B 参考重写 | C 需求参考>
 * 旧实现参考：<旧仓库路径>（理解意图用，未复制代码）
 * 官方复用：<用到的官方 API>
 * 前提检查：<旧实现的前提是否仍成立>
 */
```

## 6. 完成判据

一个模块算"完成"必须同时满足：

- [ ] 头注释按 §5 模板写全
- [ ] 官方有现成能力的地方**没有**自己实现
- [ ] 不写 profile 文件、不调 pnpm（除非走官方 `operations`）
- [ ] 有测试，且测试 import **构建产物**（`dist/*.js`），不是源码
- [ ] 若涉及官方契约，有对应的契约测试（如平台表、slot 注册面）
## 7. 工具使用红线（事故驱动，2026-09-18 记录）

### 7.1 绝不把「部分读取」的内容整文件回写

**事故**：为了把备份类型收敛到 types.ts，用 read 读了 src/envManager.ts 再 write 回写。
read 默认只返回 2000 行，而该文件超过这个上限 —— 回写把文件尾部整段截掉（丢失整个备份段）。

**根因**：read 的返回值同时包含 `lines` 与 `totalLines`，但回写时没有比对二者。

**硬规则**：
- 若 `lines.length !== totalLines`，说明读到的是**片段**；此时**禁止**用它做整文件 write。
- 需要改大文件的局部时，用 `edit`（字面替换）而不是 read+write。
- 需要整文件重写时，先确认 `lines.length === totalLines`；否则分批读全再拼，或用 edit。
- 大文件（>1500 行）默认按"只改局部"处理。

### 7.2 破坏性文件操作前的自保

- 大文件在动手前先做一份副本（`cp x.ts /tmp/x.ts.bak`），或在 git 里先提交一次。
- 本仓库尚未建首个 commit，这会让事故无法用 git 回滚 —— 建仓后应尽早提交首个快照。

### 7.3 恢复源优先级

1. 作者本人的上下文（冷启动原作者重写，保真度最高）
2. 构建产物（dist/*.js 含完整实现，dist/*.d.ts 含完整类型面）
3. 测试文件（行为契约，可当正确性依据）

事故恢复实例：envManager.ts 被截断后，用 dist/envManager.js（完好的编译产物）+
env-dev 的原始意图重建；tests/envManager.test.mjs 作为验收依据。
### 7.4 警惕自证式测试（本轮最贵的一课）

**事故**：host 的 `diagnose` 返回裸 jobId 字符串（违反自家 `docs/REST-CONTRACT.md` 的 `{ jobId }`），
而 `tests/index.test.mjs` 的 12 个 op 分派用例**全部通过**——因为测试里的 `makeJobs()` 桩件
返回的也是字符串：**测的是我自己的错误实现，而不是契约**。

后果：真实浏览器里 `report.counts` 读字符串属性抛错 → 官方 SlotErrorBoundary 接住 → **整页空白**。
单测全绿、SSR 全过，用户看到的是白屏。

**规则**：
- 桩件要按**契约**建模，不是按实现建模。实现与契约不一致时，测试应当红。
- 契约里写死了形状的边界（如首包 `{ jobId }`），就写一条**钉形状**的断言，
  并且刻意**不接受**"宽容"形式（见 `tests/index.test.mjs` 的 `jobIdOf()`）。
- **单测 + SSR 绿 ≠ 用户能用**。任何"渲染出来"的断言，最终要有一条走真实浏览器的路径
  （`tools/cdp-shot.mjs` + `tools/e2e-visual.mjs`）。
- 独立审计者的价值在于**不共享作者的盲区**。作者自查发现不了自己的系统性错误，
  这不是态度问题，是信息问题。

### 7.5 「可连接」不等于「可用」（2026-09-19 记录）

**事故**：startEnvironment 用「TCP 端口可连接」当作实例就绪。真机实测它 1018ms 就返回
ok=true 并给出地址，而那一刻 GET / 返回 **404**（服务器已绑定端口、路由尚未注册），
1000ms 之后才是 **401**（官方 browser-auth 的未授权应答，说明 GUI 路由已注册）。
用户拿到的是一秒钟内打不开的地址。

**同一轮的第二处**：createEnvironment 不带模板时走官方 DEFAULT_PROFILE_BUNDLES =
['@deepseek-ai/dsh-base']（只有 base，没有 web server），于是**新建的环境必然启动超时** ——
30 秒干等，最后一句「请看启动窗口的输出」。264 个单测全绿、16 项视觉 e2e 全绿都没发现，
因为 e2e 跑的是「复制 pm-test 的文件 + pnpm install」的临时 profile，
**从没调用过我们自己的 createEnvironment**。

**规则**：
- 判据取**用户能观察到的那一步**。不是「端口在监听」，而是「官方 HTTP 端点已按官方语义应答」。
  能观察到的事实在哪一层，判据就取到哪一层。
- **e2e 的起点必须是产品的起点**。跑在别人造好的 profile / 别人准备好的状态上，
  等于绕开了最该验证的那段代码；验收路径要自己从 0 走到用户看到的结果。
- 测试绿 ≠ 用户能用，这一点已在 §7.4 记过一次；§7.5 是它在**生命周期与就绪**上的同型复发。
  凡新增一条「等待某外部条件」的逻辑，都要问：**条件成立时，用户能做的事真的能做成了吗？**
- 该提前判定的事不要拖到超时。能读到官方事实（如环境的 bundle 层栈）就在动手前判定并
  给出可操作的说明（「请启用 X」而不是「请看窗口输出」）。
- 官方常量优先：层栈与模板来自官方 PROFILE_TEMPLATES / DEFAULT_PROFILE_BUNDLES，
  不抄成我们自己的名字表——抄一份就是一份会过期的假事实。
